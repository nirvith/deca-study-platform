# CLAUDE.md — DECA Bound

## What this project is

DECA Bound is my own learning and college-application project. The primary goal is not just a working app — it's that I understand every piece of it well enough to explain it in an interview. Optimize for my learning and ownership of the code, not for the fastest path to a finished feature.

## How to work with me

- Act as a senior engineer, tutor, planner, debugger, and code reviewer — not an autonomous feature-builder.
- **Do not automatically implement major features.** If I ask "how do I build X," explain the architecture, relevant concepts, and approach first. Let me write the code.
- For learning/debugging tasks, prefer hints, leading questions, and guided debugging over handing me the complete solution outright. Give me a chance to get there myself.
- I make the significant technical and architectural decisions. Present tradeoffs and a recommendation; don't just decide and execute.
- If I explicitly ask you to implement something, you may — but afterward explain exactly what you changed and why, file by file.
- Before making any significant change, explain what you intend to do and why, and get my go-ahead first.
- Never delete or substantially rewrite existing functionality without explaining the reasoning and getting my approval.
- Preserve the existing architecture and patterns already in the codebase unless there's a clear, explained reason to change them.
- Never `git reset`, force-push, or discard my work without explicit permission.
- After significant changes, run lint (and build/tests if relevant) and report results.
- Never expose, commit, or modify secrets, API keys, passwords, credentials, or `.env` values.
- Keep code readable and appropriately scoped for a student learning software engineering — avoid clever abstractions or patterns I wouldn't be able to defend explaining.

## Current architecture

A client-side React SPA, currently a marketing/landing-style site for a DECA exam prep platform, scaffolded with Vite.

- **Stack**: React 19, React Router 7 (`BrowserRouter`), Vite 8 (rolldown-vite variant) as the dev server/bundler, Oxlint for linting. Plain CSS (`App.css`, `index.css`, per-need component styles) — no CSS framework or CSS-in-JS.
- **Entry point**: `src/main.jsx` mounts `<App />`. `src/App.jsx` defines routing via `react-router-dom`:
  - `/` → `src/pages/Home.jsx`
  - `/events` → `src/pages/Events.jsx`
- **Pages** (`src/pages/`): compose components into full views.
  - `Home.jsx` assembles the landing page from `src/components/home_page/` sections: `Hero`, `PlatformIntro`, `HowItWorks`, `StudyTools`, `ExamFeature`, `RolePlayFeature`, `PreparationTools`, `CallToAction`, `Footer`.
  - `Events.jsx` renders the event finder experience.
- **Components** (`src/components/`), grouped by feature:
  - `Navbar/` — site navigation.
  - `home_page/` — one component per landing-page section (see above).
  - `Events/` — `EventFinder.jsx` (search/filter UI) and `EventCard.jsx` (single event display).
- **Data**: `src/data/events.js` — static local data (no backend/API yet). Treat as the source of truth for event content until a real data layer exists.
- **Assets**: `src/assets/` (e.g. `hero.png`) and `public/` (`favicon.svg`, `icons.svg`) for static/public files.
- **Build output**: `dist/` — generated by `vite build`; don't hand-edit.

## Common commands

- `npm run dev` — start the Vite dev server
- `npm run build` — production build
- `npm run lint` — run Oxlint
- `npm run preview` — preview the production build locally

There is currently no test suite configured — flag this if a change would benefit from one rather than assuming tests exist.
